9. TROUBLESHOOTING AND KNOWN LIMITATIONS

ModuleNotFoundError:
Run step 2 using the same .venv\Scripts\python.exe interpreter as the launch
commands. Do not mix a global Python installation with the project environment.

Broker connection failure or timeout:
Test-NetConnection broker.hivemq.com -Port 1883
If TcpTestSucceeded is False, check the connection and whether the network permits
MQTT traffic. Use the offline test for storage/charts until connectivity returns.
A successful TCP check does not itself prove MQTT delivery.

Subscriber connects but receives nothing:
Confirm both programs use the same broker and topic, and start the subscriber
before the publisher. Defaults are in src\config.py. If using --topic, supply the
same value to both programs. Another running instance with the same client ID
can interrupt the connection.

Database is locked:
Stop duplicate writers and finish or close any open edit transaction in a SQLite
browser, then retry. Keep the application to one subscriber during the demo.

Invalid sensor data:
The subscriber rejects non-numeric, non-finite and out-of-range measurements and
prints 'store error' instead of saving them. Redelivered zone messages with an
existing message_id are skipped as duplicates. If an unexpected row appears,
stop ingestion and inspect it; preserve the database before making corrections.

Empty database or too few readings for charts:
Run src\offline_pipeline.py as in step 3 to populate data and regenerate outputs.

Data preservation:
Do not use seed_database.py --reset during routine setup/testing. That option
deletes existing sensor rows. For a backup, stop the subscriber and other writers,
then copy data\iot_data.db to a separately named backup before changing data.
